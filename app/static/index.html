Kubernetes 本地盘上线预检

在 Pod 启动前，先算清楚本地 PV 能同时喂饱几个 Pod

API 文档

1. 导入清单

≤ 16 块 PV · ≤ 6 个 Pod

也可以把 JSON 直接粘贴到下面，然后点“开始试算”。

填写最低上线数后给出发布判定：够数显示「可上线」，上界仍不够提示「推迟」，其余「待复核」。 填写时限后到时停止搜索，输出当前最好分配与可启动数量上界；不填时限则完整精确求解。

清单格式说明 
{
  "persistent_volumes": [
    {"name": "pv-a-fast-100", "node": "node-a",
     "storage_class": "local-fast", "capacity_gi": 100}
  ],
  "pods": [
    {"name": "postgres-0",
     "candidate_nodes": ["node-a", "node-b"],
     "claims": [
       {"name": "pgdata", "storage_class": "local-fast", "capacity_gi": 100},
       {"name": "pgwal",  "storage_class": "local-fast", "capacity_gi": 50}
     ]}
  ]
}
  • PV：name、node、storage_class、capacity_gi（Gi 整数，也接受 "100Gi"）。
  • Pod：candidate_nodes 为可调度节点；claims 为需要独占的 PVC。
  • 规则：StorageClass 相同且容量足够；一块 PV 只给一项 PVC；同一 Pod 的卷必须同节点。
